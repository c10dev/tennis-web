# 시즌 방: 친구와 함께하는 테니스 투어 (M9, ADR-032 → ADR-033)

2026-10-18 텍스트 게임으로 피벗(ADR-032). 2026-10-19 kickru와 같은 루프에서 벗어나도록 재설계했다(ADR-033).
핵심은 세 가지다: **친구들과 한 시즌을 같이 뛴다**, **투어 일정을 직접 짠다**, **팀을 꾸린다**. 3D 퀵매치·중계는 `?legacy=1`.

## 1. 루프
- **방:** 2–8명이 초대 코드로 모인다. 모두 같은 월드(시드), 같은 출발선. AI 선수 약 250명이 투어를 채운다. 혼자면 "연습 시즌".
- **구간 계획 (한 사람 2–5분):** 12주 달력에서 대회를 고르고, 팀(코치·피지오·에이전트)을 정리하고, "준비 완료".
- **구간 진행:** 모두 준비하거나 마감(직전 구간 뒤 12시간)이 지나면 진행. 미제출자는 직전 계획(없으면 기본 계획)으로 뛴다. 모든 기기가 같은 시드와 같은 계획 로그로 같은 엔진을 돌려 같은 결과를 본다.
- **리포트:** 방 순위, 친구끼리 맞붙은 경기(텍스트 중계), 헤드라인, 스태프 코멘트, 내 대회 결과.
- **시즌:** 4구간(구간마다 메이저 하나, 마지막에 파이널스). 끝나면 방 시즌 결산 → "다음 시즌"으로 이어가면 선수는 나이를 먹고 커리어가 계속된다.

## 2. 선수 만들기 (공정한 출발)
- 이름, 국적, 플레이 스타일, **재능 포인트 10**을 6그룹(서브·포핸드·백핸드·리턴·피지컬·멘탈)에 나눈다.
- 모든 사람이 18세, OVR 66, 같은 숨은 잠재력(16.2), 같은 시작 랭킹 포인트(풀 150위 수준)로 출발한다. 재능은 OVR을 바꾸지 않고 모양만 바꾼다(다른 그룹이 조금씩 내려간다).
- 표시 능력치: 엔진 1–20 레이팅을 6그룹 0–100으로(`× 5`의 그룹 평균), OVR = `overall() × 5`.

## 3. 투어 일정 짜기
- 구간 = 12주. 대회마다 주(1–12)와 기간(메이저 2주, 나머지 1주), 지역(오세아니아·아시아·유럽·북미·중동), 표면.
- 계획 = 고른 대회 목록. 주가 겹치면 안 된다. 대회 카드는 등급, 표면, **방어할 포인트**(작년 같은 구간에 딴 것), **본선 예상**(직행 / 예선 / 대기), **피로 예상**을 보여 준다.
- 본선에 못 들면: 퓨처스는 항상 출전(예선 통과 처리), 챌린저·250은 예선(통과 확률은 레벨 대 예선 수준), 마스터스·메이저는 에이전트 와일드카드가 없으면 불가.
- 주 단위 컨디션: 대회 주는 피로 +(기본 + 경기당), 연속 대회 +, 지역 이동 +. 쉬는 주는 피로 −(피지오가 키운다). 부상은 대회마다 피로·체질·나이·피지오로 굴린다.
- 성장 = 나이 × 잠재력 여유 × 코치 × 사기 × (경기 수 보정) × (훈련 주 보정). 매주 대회만 뛰면 훈련이 부족하고, 너무 쉬면 경기 감각이 부족하다.

## 4. 팀 꾸리기
| 역할 | 효과 | 품질(1–5)이 올리는 것 |
|---|---|---|
| 코치 | 성향(공격·수비·멘탈·올라운드)의 두 그룹을 더 키운다 | 성장 배율 |
| 피지오 | 쉬는 주 회복, 부상 확률 | 회복 배율, 부상 감소 |
| 에이전트 | 스폰서 수입, 메이저·마스터스 와일드카드 | 수입, 와일드카드 확률 (상금 10% 수수료) |
- 시장: 역할마다 4명, 구간마다 일부 바뀐다. 계약 4구간, 구간마다 연봉. 해고하면 한 구간 연봉 위약금. 돈이 모자라면 고용할 수 없다.
- 무적 조합이 없도록 품질이 높을수록 연봉이 가파르게 오른다.

## 5. 텍스트
- 한국어만(영어는 TD-080). 헤드라인은 우리 문체로 새로 쓴다. 커뮤니티 밈 댓글 대신 **스태프 코멘트**(내 팀이 이번 구간을 말한다)와 **방 피드**(친구들의 결과, 맞대결).
- 큰 경기(메이저 4강·결승, 파이널스 결승, 친구끼리의 경기)는 엔진 이벤트로 텍스트 중계.
- 피한다: 레퍼런스 게임의 문구·이벤트 소재를 옮기지 않는다(ADR-033).

## 6. 서버 (lockstep)
- Supabase: `rooms`(시드, 마감 시간, 현재 구간), `members`(닉네임, 선수 설정), `plans`(구간별 계획, 준비 여부), `swings`(진행 기록, 상태 해시). 익명 로그인.
- 서버는 시뮬레이션하지 않는다. `advance_swing` RPC가 전원 준비 또는 마감을 서버 시각으로 판정해 구간을 원자적으로 넘긴다. 클라이언트는 계획 로그를 접어(fold) 상태를 만들고, 구간별 해시로 불일치를 감지한다.
- 개발·e2e: `MemoryRoomServer`(테스트), `LocalRoomServer`(localStorage, 같은 브라우저 두 탭).

## 7. 밸런스 목표 (`npm run room -- --n 200 --seed 1`)
| 지표 | 목표 |
|---|---|
| 똑똑한 일정 대 무작위 일정, 시즌 랭킹 포인트 | +15–35% |
| 최고 스태프 조합의 우위 (같은 예산, 시즌 포인트) | 다른 조합 대비 +20% 이하 |
| 같은 출발 4인 방에서 시즌 1위가 정해진 정책에 쏠림 | 한 정책 1위 비율 70% 이하 |
| 시즌 끝 랭킹 (같은 출발, 기본 정책) | 중앙값 60–140위 |
| 구간 하나 처리 (Node) | < 150 ms |

### 측정 (2026-10-19, `npm run room -- --n 400 --seed 7`)
똑똑한 일정 대 무작위 +39% (목표 밖, TD-086) · 스태프 역할 간 차이 14% · 최다 우승 일정 36.5% · 시즌 끝 랭킹 중앙값 117위 · 구간당 43 ms(4인 방).
출발은 OVR 70, 시작 랭킹 약 150위(풀에서 그 순위의 수준에 맞춤; 승인안의 66에서 측정 후 조정).
**룸 컵:** 구간마다 방 멤버끼리 토너먼트(랭킹 포인트 없음) — 친구끼리 매 구간 맞붙게 한다.

## 8. 보류
서버 측 검증(클라이언트를 믿는다), Toss 로그인, 방 채팅, 14세 주니어 단계(코드는 있으나 방 모드에 미노출), 경기 중 선택, 3D 하이라이트.
